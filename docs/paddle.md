# PaddlePaddle export

LibreYOLO supports an experimental PaddlePaddle export and CPU inference path
for YOLO9 detection. The graph is exported to static ONNX, converted with
X2Paddle, and packaged with LibreYOLO metadata so the exported directory can be
loaded through the same factory as other runtimes.

## Install

Use Python 3.10-3.12. WSL2 with Ubuntu 22.04 is the validated Windows path.

```bash
pip install "libreyolo[paddle]"
```

The extra pins the measured CPU toolchain: PaddlePaddle 2.6.2, X2Paddle 1.6.0,
and ONNX 1.17 or earlier. Newer Paddle releases reject parts of the static code
generated by X2Paddle 1.6.0, so LibreYOLO fails early on an unvalidated version
instead of producing a questionable artifact.

## Export and predict

Python:

```python
from libreyolo import LibreYOLO

model = LibreYOLO("LibreYOLO9t.pt")
artifact = model.export(format="paddle", dynamic=False)

paddle_model = LibreYOLO(artifact, device="cpu")
results = paddle_model("image.jpg")
```

CLI:

```bash
libreyolo export model=LibreYOLO9t.pt format=paddle dynamic=false
libreyolo predict model=weights/LibreYOLO9t_paddle source=image.jpg device=cpu
```

The artifact is a directory containing `model.pdmodel`, `model.pdiparams`, and
`metadata.yaml`. Conversion-only generated Python is not included.

## Current boundary

- Supported: YOLO9 detection, FP32, batch 1, fixed square input, CPU runtime.
- Not supported: dynamic shapes, FP16, INT8, embedded NMS, or GPU runtime.
- RF-DETR is blocked before tracing. Its export requires ONNX opset 17 and
  GridSample, while X2Paddle 1.6.0 supports opset 15 or lower and does not map
  GridSample.
- Other model families and tasks remain blocked until they have conversion,
  raw-output, metadata, reload, and public-result parity evidence.

See [export_support.md](export_support.md) for the canonical family/task matrix.
